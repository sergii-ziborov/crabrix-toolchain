# Security

Report vulnerabilities privately to the repository owner through GitHub's private vulnerability reporting when available. Do not attach credentials, private app projects, signing keys or user data to public issues.

Release inputs are pinned and verified before extraction. Unknown revisions, missing digests, unavailable bootstrap archives and unpinned build environments stop the build. The normal source build has no publishing credential. A protected publish step signs the external artifact descriptor after functional and provenance verification. `scripts/toolchain_descriptor.py sign` refuses candidate artifacts, a dirty build, an incomplete environment lock, and missing T01–T06 gate results. It requires an Ed25519 private key outside this repository. The public `tests/fixtures/test-keyring.json` and deterministic test seed are test-only; they are never a production trust root. The app must use its embedded production keyring to verify the descriptor and hashes before bundling compiler assets; phones do not download compiler updates.

The descriptor signs the exact UTF-8 bytes of its JSON payload after the `Crabrix.ToolchainDescriptor.v1\n` domain prefix. The envelope contains `keyID`, `payloadBase64`, and `signatureBase64`; verification uses the decoded payload bytes directly and checks every release file, including notices and compatibility evidence. Compatibility results must name the exact compiler/sysroot SHA-256 values and app/runtime Git revisions used for the gates. The descriptor is external to its own file inventory. Key rotation requires an app update with overlapping trusted public keys, never a keyring downloaded from the release host.

The compiler still processes untrusted Rust source inside the app's Wasm runtime. Runtime memory, fuel, deadlines, filesystem rights, output quotas and cancellation are enforced by the app/runtime integration, not by a toolchain archive signature alone.
