# Additional release notice inputs

The release `vendor-notices.zip` is generated by `scripts/collect-vendor-notices.py`
from the exact Rust `vendor/` tree in `toolchain.lock.json`, these checked-in
standard license texts, and three additional WASI libc source notices.

`spdx-v3.29.0/` contains the named plain-text files from
[`spdx/license-list-data` v3.29.0](https://github.com/spdx/license-list-data/tree/31ba1a50e5397e00a304dbadc76531740e89ee48/text),
commit `31ba1a50e5397e00a304dbadc76531740e89ee48`. The collector pins each
file's SHA-256. They are included when a vendored crate declares a standard
license expression but its archive does not carry a separate notice file.
The index distinguishes these standard texts from a crate's own files.

`source-notices/` contains the cloudlibc and musl notices in the pinned
`WebAssembly/wasi-libc` source revision
`2fc32bc81b9f07f8d9525edea59bfbaf760c06d6`. Their source files are
`libc-bottom-half/cloudlibc/LICENSE`, `libc-top-half/musl/COPYRIGHT`,
and `fts/musl-fts/COPYING`, respectively. They supplement the
primary licenses in `licenses/third-party/`.

These inputs do not change the MIT terms of this builder recipe or replace
the original component notices. The release archive is an inventory of
their actual source and declared terms.
